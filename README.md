# PLC Engineering AI

Mitsubishi PLC / GX Works2·3 작업을 위한 **로컬 단일사용 개발 기반**입니다.
초기 별칭은 PanelLab입니다. 한국어 반응형 UI이며 CPU 모델은 기본 미정입니다.
기존 Copilot Studio 8개 에이전트의 역할·지침·연결 설정을 바꾸지 않습니다.

> **공개 배포 금지.** 로그인·다중 사용자 권한·운영 보안은 미완성입니다.
> `0.0.0.0`, LAN 바인딩, 터널, 포트 공유, 리버스 프록시로 노출하지 마세요.
> PLC 직접 다운로드·설비 자동제어는 제공하지 않습니다.

## 실행 (Windows PowerShell, Python 3.11 이상)

저장소 폴더에서 다음 명령을 실행합니다. 무료 오픈소스 패키지만 사용합니다.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --no-proxy-headers
```

브라우저에서 `http://127.0.0.1:8000`을 엽니다. HTML 파일을 직접 여는 방식은 지원하지
않습니다. 서버 종료는 실행한 터미널에서 `Ctrl+C`입니다.
개발 서버를 스마트폰에 노출하지 마세요. 모바일 UI는 같은 PC 브라우저의
개발자 도구에서 390px/768px 너비로 먼저 확인하세요.

1. **프로젝트 관리**에서 프로젝트를 생성하고 GX Works 버전·CPU·요구사항을 저장합니다.
2. **PLC 도면 분석**에서 파일을 업로드하고 추출 결과·원본을 확인합니다.
3. **PLC 코드 생성**에서 원본 텍스트를 먼저 저장합니다. 이후 편집은 수정안으로 보관됩니다.
4. **오류 자동 수정**에서 수동 수정안을 원본과 비교하고 확인란을 체크한 뒤 승인합니다.
   승인본은 새로운 버전이며 미검사 상태입니다. 원본은 덮어쓰지 않습니다.

## 이번 기반의 범위

| 구분 | 구현 / 현재 상태 |
|---|---|
| 화면 | 대시보드, AI 작업실, 도면 분석, 작화 작성, 코드 생성, 오류 검사, 오류 자동 수정, PLC 검증, 보고서, 프로젝트 관리, 작업 이력, 설정 — 12개 독립 화면 |
| 프로젝트 | 이름·GX Works·CPU·설비 요구사항, SQLite 영속 저장, 실제 저장 작업 이력 |
| 파일 | 원본 비공개 보관, SHA-256, 확장자·시그니처·크기 검사, 프로젝트별 조회 |
| 무료 전처리 | PDF 텍스트·표(pdfplumber), XLSX(openpyxl), CSV·TXT(표준 라이브러리) |
| 이미지 / 스캔 | JPG/JPEG/PNG 구조 검증·이미지 미리 보기. OCR 미구현으로 명시 |
| 코드 | PC·모바일 공통 경량 텍스트 편집기, 원본/수정안/승인본 분리·전후 비교 |
| 채팅 기반 | 기존 브로커용 서버 토큰 중계, Web Chat **4.18.0**, 한국어, Direct Line 상태 구독·재연결 |
| 실제 AI | 기본 비활성. AGENT01 대상·실제 응답·01→02~08 실행/입출력 미확인 |
| 아직 미구현 | OCR, PDF 페이지 미리 보기, 래더 렌더러, 변수·I/O 의미 해석, GX 네이티브 파일, 검사/실제 컴파일/시뮬레이션, AI 결과 수집, PDF/Excel 보고서 |

화면의 개수·파일 수는 실제 로컬 데이터입니다. 검사·연결·전문 에이전트 실행 성공을
생성하지 않습니다. **텍스트 추출 ≠ AI 분석 ≠ 실제 GX 컴파일 ≠ 설비 시험**입니다.
수정안의 사용자 승인도 PLC 안전성 승인이나 검사 통과를 뜻하지 않습니다.
수정 전후 비교는 같은 줄 위치를 비교하며 의미 기반 diff나 PLC 검사가 아닙니다.
Monaco는 모바일 미지원이므로 이번에는 의존성 없는 textarea를 사용합니다.

## 환경변수와 기존 브로커

`.env.example`은 변수 이름 참고용입니다. `.env` 자동 로드는 하지 않습니다.

| 변수 | 기본값 / 의미 |
|---|---|
| `PLC_DATA_DIR` | 저장소의 `.local-data` — 별도 비공개 데이터 디렉터리 |
| `PLC_ENABLE_BROKER` | `false` — 실제 브로커 호출 차단 |
| `PLC_BROKER_SEALED` | 미설정 — 서버 환경변수 전용, 브라우저·Git·로그에 입력하지 않음 |

**실제 SEALED는 제공받거나 사용하지 않았습니다.** 원문 HTML의 노출된 값을 복사하지
마세요. 기존 운영 담당자와 대상 에이전트·사용량·비밀값 관리/회전 절차를 확인한 후,
승인된 값을 서버 프로세스 환경에 안전하게 설정해야 합니다. 채팅은 기존 서비스의
라이선스·요금 정책에 따르며 무료라고 보장하지 않습니다.

기존 경로를 그대로 보존합니다:

```text
브라우저: 연결 버튼 클릭
  → Web Chat 4.18.0 라이브러리 확인
  → POST /api/chat/token (로컬 세션 확인)
  → 서버: 고정된 기존 HTTPS 브로커에 POST
      https://dl-broker-juwon-4jt3z.azurewebsites.net/api/directlineToken
      body = JSON {sealed: <서버 환경변수>}
      Content-Type 헤더 추가하지 않음 / 리다이렉트 따르지 않음
  → HTTP 200 / JSON / token 문자열 검증
  → 브라우저에 단기 token만 반환 (no-store)
  → createDirectLine({token}) / renderWebChat(locale: ko-KR)
  → 실제 Direct Line Online 상태 확인
  → startConversation 이벤트 (from.id = 'user')
```

고정 `user` ID는 기존 시작 이벤트 호환용일 뿐 인증·권한의 근거가 아닙니다.
객체 생성이나 에이전트 답변 문장을 연결/호출 성공으로 계산하지 않습니다.
Direct Line Online은 채널 연결만 의미하며 대상이 실제 AGENT01인지 별도 확인해야 합니다.
기본 상태에서는 CDN 및 브로커에 호출하지 않습니다. 토큰은 브라우저 메모리에서만
사용하며 서버 비밀값과 토큰 응답 본문을 기록하지 않습니다.
페이지 이동 시 채팅 연결을 종료하며 대화는 로컬 DB에 보관하지 않습니다.

프로젝트·파일·작업 유형은 **자동으로 에이전트에 전송하지 않습니다.**
Web Chat의 직접 첨부 버튼도 확인 전에는 숨깁니다.
Direct Line 첨부/upload API 및 텍스트 전달은 공식 지원 범위와 별개로
이 환경에서 파일 업로드 허용·4.18 호환·01→03 원본 전달·토픽 매핑을 확인해야 합니다.
`channelData`만 넣어 전달이 완료됐다고 간주하지 않습니다.
XLSX는 기본 직접 전달에 의존하지 않고 서버 추출만 제공합니다.
기존 에이전트 대신 PLC 판단 AI를 만들거나 유료 이미지 AI를 도입하지 않았습니다.

## 보관·파일 안전성·한계

- 원본은 `<PLC_DATA_DIR>\files\<서버 UUID>.<검증된 확장자>`에 보관됩니다.
  원래 파일 이름을 경로로 사용하지 않습니다. 메타데이터와 추출/코드 버전은
  `local.sqlite3`에 저장합니다. `/static`은 `web` 폴더만 제공합니다.
- 파일당 15MiB, PDF 40페이지, 이미지 2천만 픽셀, 전체 원본 250MiB/100개,
  프로젝트 50개, 텍스트 버전 500개입니다. 한 번에 파일 한 개만 처리합니다.
- 업로드 스트림은 30초, 별도 파서 프로세스는 25초 제한을 적용합니다. UNIX는 추가 CPU·주소 공간 제한이
  있지만 Windows에서는 OS 수준 메모리 격리를 보장하지 않습니다.
  알려진 제한을 통과한 악성 문서까지 안전하다고 보장하거나 바이러스 검사하지 않습니다.
- XLSX는 압축 항목 2,000개 / 총 해제 80MiB / 개별 30MiB / 압축률 200배 제한,
  매크로·외부 링크 거부, 수식 미실행입니다. 표는 최대 10,000셀,
  시트 20개 / 시트 2,000행·101열입니다. 문자·셀 제한 시 일부 추출로 표시합니다.
  숫자 셀의 사용자 지정 표시 형식(예: 숫자 123을 00123으로 표시)은 재현하지 않습니다.
  문자열 `"00123"`은 유지합니다.
- CSV/TXT는 UTF-8(BOM 포함), BOM UTF-16, CP949를 엄격하게 디코딩합니다.
  바이너리 제어 문자는 거부합니다. 추출 텍스트는 최대 150,000자입니다.
  CSV 구분자는 쉼표·세미콜론·탭을 탐지합니다. 잘린 CSV는 부분 추출로 표시됩니다.
- 이미지·스캔은 OCR 필요 상태입니다. OCR로 도면 기호·회로 연결 정확성을 주장하지 않습니다.
  PDF 표 추출도 원본과 대조해야 합니다.
- 파싱 실패/제한 시간 초과/형식 검증 실패 업로드는 임시 파일까지 제거합니다.
  필수 파서 의존성 누락도 503 오류로 명시하고 미검증 파일을 보관하지 않습니다.
  기존 원본·버전은 변경하지 않습니다.
- HTTP loopback 접속·Host·동일 Origin·랜덤 로컬 세션 헤더를 확인합니다.
  CORS를 인증으로 사용하지 않습니다. 이 보호는 로그인이나 사용자 격리가 아닙니다.
  API는 의도적으로 동일 PC의 단일 사용자만 대상으로 합니다.
- `.local-data`, `.env`, 가상환경은 Git 제외입니다. Windows에서는 상위 폴더의
  ACL을 상속하므로 전용 Windows 계정과 비공유 폴더를 사용하세요.
  자동 만료·사용자별 삭제 UI·암호화 저장·백업은 미구현입니다.
  보관 기한과 삭제 정책은 운영 전 결정해야 합니다.
  개발 데이터 전체를 폐기할 때는 서버 종료 후 **정확히 확인한 전용 데이터 폴더만**
  관리자가 삭제하세요. 저장소나 사용자 홈을 삭제하지 마세요.

## 검증

로컬 API 테스트는 네트워크 외부 호출 없이 임시 데이터 폴더와 mock 브로커만 사용합니다.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

테스트 항목: 영속성·실제 이력, loopback/Host/Origin/세션 차단, CSV 한글·인코딩·원본
바이트/해시 보존, 경로·위조 확장자·빈 파일·용량·압축 폭탄 거부, XLSX 문자열·수식 보존,
PNG/JPG/JPEG의 OCR 필요 표시, PDF 40페이지 초과 거부, 수정 승인/원본 보존/중복 승인 거부,
브로커 비활성/비밀값 미설정 시 외부 호출 없음, mock 브로커 본문·헤더 계약,
잘못된 브로커 응답 거부, 파서 시간 초과 시 임시 원본 정리입니다.

실제 Chromium 브라우저 테스트는 개발 도구를 추가 설치한 뒤 실행합니다.
임시 서버·임시 데이터 폴더를 자동 생성하고 종료/정리하므로 실제 프로젝트를 변경하지 않습니다.
이 테스트는 외부 네트워크 요청을 차단하고 발생 여부도 검사합니다.

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m playwright install chromium
.\.venv\Scripts\python.exe .\tests\browser_smoke.py
```

이번 구현 환경에서 **Python 3.12 / Windows, API 테스트 15개 통과** 및 다음
실제 Chromium 자동화 검증을 수행했습니다.

- PC 1440px, 태블릿 768px, 모바일 390px 너비에서 12개 화면 및 문서 가로 넘침 없음,
  모바일 메뉴 열기·화면 전환. 실제 휴대전화 하드웨어 시험은 아닙니다.
- 프로젝트 생성 → 새로고침 후 복원 → 실제 CSV 업로드/추출 → 다운로드 바이트 일치,
  위조 PDF 업로드 실패. 데이터가 있는 상태의 12개 모바일 화면도 확인했습니다.
- 원본 코드 저장 → 수정안 저장 → 전후 비교 → 확인란 없을 때 승인 차단 →
  사용자 승인 → 승인본 표시와 원본 보존.
- JavaScript 페이지 오류 및 기본 설정의 외부 요청 없음. 데스크톱/모바일 스크린샷도
  직접 확인했습니다. Node.js는 없지만 Chromium에서 실제 스크립트 실행을 확인했습니다.

`requirements.lock`은 이 검증 환경과 일치하는 실행 의존성 고정본입니다.
`requirements.txt`는 호환 범위의 원본입니다. 운영 보안 검토, 실제 브로커/에이전트 호출,
GX 컴파일·시뮬레이션·설비 시험은 **수행하지 않았습니다**.
